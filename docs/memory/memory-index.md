## Log (newest first)
- [2026-09-12 The archived bucket](log/2026-09-12-archived-bucket.md) - retired curated names move from `aliases`, which resolve in all three buckets, to `archived.<source>`, which resolves in that source only and is never asserted; `archived_on` is the date it was archived, not a last-seen date. Five ASN labels archived, `HGTLD` reseeded because it is live; a 12-entry allowlist pins the before/after resolution diff
- [2026-09-10 The nightly syncs its build inputs](log/2026-09-10-nightly-input-sync.md) - the scrape holds its inputs for 32 minutes before the build reads them, so `update-data` re-points HEAD at current `main` and adopts `data/manual/` before building, and the consumer guard narrowed to `data/source/` plus `data/generated/` - the paths the patch actually writes. `git restore`, not `git checkout <tip> -- <path>`, which defaults to overlay mode and resurrects deleted files. `rebase` now measures staleness from `EXPECTED_HEAD` and script safety from the job's own `HEAD`, because sync makes them different commits
- [2026-09-09 httpx to httpx2](log/2026-09-09-httpx2-migration.md) - `httpx2` is a same-API fork of `httpx` 0.28.1, our exact pin, so the migration is a rename with no behavior delta in our call surface. The real work was ~45 string `patch("httpx.Client")` targets no linter can see; they fail loudly only because `httpx` is fully uninstalled. SSL now anchors on the OS trust store via `truststore` instead of `certifi`, which no test exercises
- [2026-09-11 VRSN-AC28 retired, label pair flapping](log/2026-09-11-vrsn-ac28-retired.md) - `VRSN-AC28` left the iptoasn table and the same four /24s went back to AS36623/`HGTLD`, reversing 2026-08-18; retire to aliases and leave HGTLD there too. Third `asn` flap in three months and each one stops the nightly commit, so the entry records three durable options (warn-only for the `asn` bucket, auto-retire via the drift-PR machinery, or collapse `source_names.asn` into aliases)
- [2026-09-09 The shared CI signing layer](log/2026-09-09-ci-signing-shared.md) - `update-data` and `check-coordinates` share one produce-patch, rebase, validate, sign, push pipeline across five `bin/ci-*` scripts. An unsigned head-branch commit blocks a squash merge, which is why the drift PR could not merge; the stale-head guard became a path comparison so an unrelated commit no longer kills the nightly; the drift branch is machine-owned via a committer check plus a lease; the credential boundary is a workflow step, because `env -u` cannot stop a child reading the parent's `/proc/<pid>/environ`
- [2026-09-09 Coordinate drift PR and its alerts](log/2026-09-09-coordinate-drift-pr.md) - `gh pr create` is refused unless the repo allows Actions to create PRs, and the alert was gated on that success, so the first real drift stranded a branch silently. Logic moved to `bin/ci-open-drift-pr`, which falls back to a compare URL and keys notifications on new content rather than PR existence; `ubuntu-24.04` because slim's 15-minute cap is a cancellation that fires no alert
- [2026-09-07 Registry agreement CSV from page state](log/2026-09-07-registry-agreement-csv.md) - ICANN's `/csvdownload` 502s on a fixed ~15.1s origin timeout and its own site never calls it, building the CSV in-browser from the page's `ng-state` JSON. The downloader fetches the page and reproduces that CSV byte for byte; `download_file()` gained a fail-closed `transform` hook, and cache validators are now keyed to the URL that issued them
- [2026-09-07 CI commit signing](log/2026-09-07-ci-signing.md) - nightly updates cross a data-only patch artifact into a clean signing job; the patch is validated before and after `git apply --cached`, and `CI_SSH_SIGNING_KEY` plus the write credential land only afterwards. Both steps are `bin/ci-*` scripts so shellcheck and scratch-repo tests reach them. Per-step timeouts, since a job-level cancellation fires no alert
- [2026-08-18 Lint scope is whole-repo](log/2026-08-18-lint-scope.md) - `bin/lint` hardcoded `src/ tests/` while the pre-commit hook ran `ruff check .`, so `scripts/` and `bin/` were never linted and carried 21 findings; default is now `.`. Rule-set pinning (`select`) still open
- [2026-08-18 HGTLD retired](log/2026-08-18-hgtld-retired.md) - AS36623/`HGTLD` left the iptoasn table entirely (prefixes now under AS397200/`VRSN-AC28`, already seeded); retire to aliases. Broke the nightly run 08-11..08-18 and the pushover alert had an invalid token, so it failed silently
- [2026-08-07 Adopt ruff default rules](log/2026-08-07-ruff-defaults.md) - ruff 0.16 grew its implicit defaults from 59 rules to 413 and broke CI; `ruff.toml` now records the rule set explicitly. Only `BLE001` is ignored (boundary handlers that log and degrade on purpose); the other 59 violations were fixed.
- [2026-07-16 iptoasn AS drift (teleinfo + verisign)](log/2026-07-16-teleinfo-asn-rename.md) - one refresh window renamed CAICT's AS (teleinfo -> "CAICT-AS-AP...") and migrated Verisign's .com/.net nameservers off "VERISIGN-AS" onto VRSN-AC28/VRSN-AC50-340, stranding both asn seeds; fix is data (reseed to live string, retire departed one to aliases). Reproduce against CI's pinned update-iptoasn artifact via gh run download, NOT iptoasn.com live-latest (which drifts ahead of CI)
- [2026-06-07 Nightly rebuild picks up manual curation](log/2026-06-07-nightly-manual-regen.md) - update-data.yaml always rebuilds (--all on IANA source change, else --preserve-asn) so data/manual/ edits propagate to data/generated/ nightly without ASN churn; was gated on data/source/ only. Keep local `iptoasn` fresh or local passes while CI (daily artifact) fails
- [2026-06-07 Verisign per-instance ASN block](log/2026-06-07-verisign-asn-block.md) - AS36616-36632 are all Verisign, one ASN per authoritative-server instance ([letter]GTLD for gtld-servers.net letters a-m plus X/Y/Z, AROOT for the roots it runs); each is a separate opaque as_org string, folded into the one VeriSign record as it appears (HGTLD/AS36623 added; other siblings not yet in data)
- [2026-06-07 as_org transit-backbone operator mapping](log/2026-06-07-asn-transit-operator.md) - fold a telecom-backbone as_org string into a DNS operator's source_names.asn only when hostname evidence is unambiguous and that ASN carries only that operator (ZDNS in China Unicom AS4837 / China Mobile AS56048); mapping is global, so misattribution is the risk
